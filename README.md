Audio105 keeps the existing finite AVAudioSession/AudioQueue two-second capture. Audio104's own helper launched correctly but the original named profile denied kern.bootsessionuuid before result-file creation. The current NezhaAudio27 service publishes the original XNU bootsessionuuid_string as one immutable BootSessionUUID property; this helper reads it through the already linked IOKit API and validates it with uuid_parse. It waits only within the existing150second startup interval. The captured result must still match the original timesync boot UUID, so old samples stay rejected. AudioQueue format, frames, callbacks, Stop/Dispose, deadlines and result paths are unchanged. This is a source-only Mac/CMS build, with no original phone or donor bytes. Native publication and fixed helper identity are compiled separately before the qualified temporary test.
