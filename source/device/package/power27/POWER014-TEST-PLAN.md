# power014：原厂固定9V、普通充电升流与完整退出

承接013已验的FCC设置/净电流响应，固定GPU015和USB829，不混其他子系统。当前源码/宿主验证完成；原生资格和真机结果分别验收。

依据当前OS4原模块：普通固定PD请求是WRITE0x2101b/4B/mV，FCC是WRITE0x2005/4B/mA。原厂buck策略先检查9V固定PDO再选档；认证过程非零时原固定PD方法抑制请求。原13读取的PDO含5/9/15/20V，无APDO。SC8585寄存器03低四位0xf是7.5V特殊档，0是11V；本机FDT原三档21/14/7.5V。本轮只改这个输入过压档位，保持保护启用。

## 模式4的同次控制流程

1. 实际PD/type10、UFP/data_role1、ICL至少1500mA、有效5/9V固定PDO、充电状态、泵关闭、电池18–35°C/3.0–4.46V及泵die低于50°C均合格，且本轮VFS日志可写，才初始化FCC500mA。旧FCC GET0保持invalid。
2. ACK后四个新的gauge时间戳确认200–650mA基线，范围差不超过150mA。
3. 独占SC8585/GPI所有者确认ID85、泵停、ADC实际输入4.5–5.5V和03低位仍为0xf，单次改为0并读回。已是11V时不重复写。原高位、其他阈值、泵模式/使能不改。
4. 单次固定9V请求。ACK后两个新的MCA/泵电压cohort实际均为8.5–9.5V、两测点差不超过500mV，才请求FCC1500mA。四个新gauge样本均值必须较基线增加至少500mA，且在1000–1650mA内。
5. 当前控制lease300秒。正常到期/正常关机降FCC500mA，条件异常降100mA；随后一次请求5V，以两个新cohort确认实际低输入，再恢复本方03原低位并读回。9V可能被接受时不能用请求前的5V样本跳过恢复请求；对已实测的新非PD附件不发PD命令。
6. 发送前拒绝与已尝试但超时分别处理，不重发升流/升压；寄存器写入不确定则停止推进、保留资源。退出所需元数据继续只读刷新，旧附件读取回执不污染新附件的30秒重试状态；实际完成后停止这些请求。

原模式2读回/模式3设置反馈保持。FCC反馈和过压档位读回分别记录；不把设置ACK报告为精确FCC读回。ICL、认证、OTG、其他保护和充电泵使能保持原所有者。

本轮资格只涉及固定9V与受限1500mA普通充电；PPS、MiPPS认证、泵直充、完整长期热策略和90W仍独立待证。
