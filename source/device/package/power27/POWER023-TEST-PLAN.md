# power023：认证时的 USB 类型更新与正常关机完成

本版修复电源认证清理失败导致正常关机等待超时的问题，继续沿 GPU015 和原
OS4 MCA 接口适配。冻结的022源码保留；其失败日志和人工回安卓后的保护后验
在电脑保存，不能把缺失日志尾部的失败记录标成 CRC 完整通过。

当前 OS4 的 qcom_subpmic_notify_cb 在0x256c读取通知数据的在线状态，在0x2578
读取第二个32位充电类型。USB_TYPE0表示状态更新。023按这两个字段区分实际
断开/接入、来源类别变化和同一适配器的PD10→PD_VERIFY11变化；后者保留
当前认证附件身份。新电源采样继续核对在线状态，已验证PD的能力表须重新
读取后才能增加电压。未知字段拒绝使用，已发送挑战和角色请求均不重放。

认证过程中允许同一附件在PD10/PD_VERIFY11之间更新。接受最终VDM6成功
报告后即跟踪可能产生的固件验证效应。错误清理先结束本方verify_process，再
撤销验证报告并检查实际状态。报告写使用21013，固件状态读使用2100b，所有
清零仍只有一次写及原有截止时间。未知效应保留所有权并拒绝恢复和增加电压。
终止的清理错误允许继续只读观测，不把它留成永远忙碌的认证任务。

正常系统关机等待本worker实际退出后调用原生IOService关机完成接口。清理
失败仍显示lifecycle=-1并保留映射；这个完成通知不表示休眠/恢复或充电成功。
认证清理失败可以停止已经确认空闲的板级资源，未知BUCK效应继续保留资源
与ADC保护，失败的quiesce不重试。原setPowerState的成功判定和异步ACK保持。

沿现有BQ总线接入只读身份查询MAC4a/4b：校验命令回显、长度和字节校验和，
仅公布化学类型和有界设备名。结果缓存于本驱动资源生命周期，休眠/失效时
撤下，恢复后使用新读取。它为后续原厂电池策略选择提供实际输入，未启用
新的JEITA、满充回充、PPS、泵使能或校准写入。

宿主同一独立对端复现022：最终VDM6后USB类型变化撤销认证，清零报告已ACK
但验证状态仍为1，清理保留owned3，worker退出失败且旧关机条件无法完成。
023同对端完整认证/清理通过。固件状态无法清零和清零ACK丢失的故障场景
保留错误、所有权及恢复拒绝，实际worker结束并单次停止可释放的本方资源。
原32项Runtime、24项认证核心、4项主电池MAC、8项身份总线、13项Runtime
认证/PC日志、17项固定PD及缓存/有界诊断通过；日志和读取器的未变证据复用。
原生编译、严格预链接和原14项电脑资格仍独立完成后才固定SHA并按文件排队。

同次真机验主电池认证、身份读取、MDY-18-EW和原厂线下的完整适配器认证、
USB_TYPE更新是否保留附件及认证状态。温度、电量、固定PDO与泵关闭等条件
满足时验9V/FCC1500及有序降流、实际5V和原OVP恢复。回电脑后检查新USB
会话、角色和一次当前session/seq正常XNU返回，完成必要Android/root后验、
自有采集退出与有界日志CRC/计数后及时释放。净充入只取日志实际连续180秒。

原安卓/root/17/只读27根/generation1 Data、原payload范围、分区禁刷和固定
复位0保持。013普通FCC、017 ADC/本驱动PM分项保留，主包不晋升；完整
高功率、温度/满充回充、PPS与泵直充仍须真实验收。
