`nezha-power=1` 保留读取与电源服务路径。
`nezha-power=2` 保留精确读回的 ICL/FCC 控制；未知读取仍阻止写入。
`nezha-power=3` 是当前 OS4 setter 后端：只在已核 5 V DCP/PD、温度/电压/泵/角色/日志条件内，且实际 ICL 已足够时，初始化 FCC500 mA，收四个新电量计样本，再请求 FCC1000 mA；真实响应不足则降至100 mA并结束，同源正常到期降至500 mA。
模式3不把 READ0x2005=0 改为有效限流值，也不把设置 ACK 或电流响应报告成精确寄存器读回；ICL 保持实际所有者设置。
控制 lease240秒沿单调时间，到期只降流。MCA 已接受但无回执时不重发升流；降流失败明确保持不确定状态。正常 XNU 收尾只记录实际回执。
013 测试包内建模式3；旧012/009镜像和主包身份保持。
`nezha-power=4`承接014固定PD后端：只在有效5/9V固定PDO、UFP角色、实际ICL/温度/电压/泵停及日志条件满足后，初始化FCC500mA、修改SC8585 USB OVP原低位15为0并读回、请求9V并收两组新电压cohort，再请求1500mA并确认四组新电流样本。300秒控制期限结束后先降流，再请求并实测5V，最后恢复原OVP。014在电脑SDP源下实际控制0次，不能当这条高压路径已通过。
所有控制模式退出均检查本方pending/未确认效果/所有权；降流或恢复失败保留资源并报告lifecycle=-1，不能确认正常关机或休眠。015修复的是这条共用完成判定，未改变升压、限流或保护参数。
