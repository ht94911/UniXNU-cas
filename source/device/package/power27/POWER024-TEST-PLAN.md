# power024：认证报告清理与同次重新接入

本版从冻结023源码继续，只修复认证报告与固件VDM诊断状态的混用。原厂字段
和023实测依据见[POWER023-RUNTIME.md](POWER023-RUNTIME.md)。GPU015、USB829f7a3、
固定PD/OVP/FCC、温控阈值、日志、Data和主包保持原实现。

WRITE21013=0收到真实MCA成功回执后，释放本方报告bit2。初始化仍读取2100b
并检查合法binary0/1；值1仅表示固件VDM诊断，不能把它当成本方报告未清零。
正向认证继续要求新随机挑战、真实HMAC、主电池成功、固件状态1及process0。
清理只有本方持有的报告才写，清零ACK丢失保留bit2/error9，不能用固件0替代
回执，也不能重放已经发送的清零写。

`NP_AUTH_OWNS_VDM_EFFECT=4`单独记录已经接受最终VDM6而完整认证尚未确认的
固件效应。完整正向认证完成后不再把这项已确认效果当成未知；提前失败时
仍需实际固件0才能释放bit4。一份报告清零ACK不能释放这项未知效应：有界
单次清零后仍1则保留bit4/error9并拒绝恢复及增压。process清理也仍须自己的
真实READ0。结构大小、命令格式、属性号及原有截止时间保持。

宿主32项认证核心和实际Runtime/MCA/Auth的16个场景已通过ASan/UBSan。
覆盖原有故障、process ACK丢失、最终VDM6未知效应、报告清零ACK丢失、旧固件
诊断1以及同次两次接入。相同独立对端运行冻结023实际core/runtime，重现
detach的state22/error9/owned2/report0/diagnostic1；024完成两次新HMAC与DFP
请求，主电池只验一次，正常worker退出。首版重连夹具曾错误把type10改为1，
该失败保留；仅修正测试对端输入后全部通过，生产修复不因夹具改动改变。
其余受影响Runtime32、缓存和有界诊断也已通过，16组统一绑定最终源码。
10个无变化组按源码/头文件依赖复用。Native、严格预链接、签名及原14项电脑资格另行完成，
固定实际SHA后才按共享文件队列领取手机，不在构建时预约。

真机同一次boot执行PC→原厂充电器/线→PC→再次原厂充电器/线→PC。第一次
接入保持完整控制和恢复观察；第二次验证独立新挑战/第二次完整认证。每次
物理换线等人类实际答复。PC段读取本方日志、报告/所有权、process、附件
身份与USB会话；固件诊断仍1可以记录，但不能省去新完整HMAC。第二段固定
PD只按实际新条件和既有控制生命周期判断，不通过重置控制器强行重复升压。
实际充入量只按日志连续180秒积分，不用聊天等待时长替代。

收齐后一次绑定当前USB身份/序号的正常XNU返回，核实际Android/root、原
payload/Data映射-pin、必要GPT目标几何与17/27Data头，取自有有界日志并核
CRC/计数，停采集和释放手机。无法完成/未知请求保留原记录，不重发。
安卓/root/17/只读27根/generation1 Data、原payload范围、分区禁刷、固定
复位0及单代理/文件协调保持。报告清理通过也不等于JEITA、满充回充、PPS、
泵或90W完成，不提前合主包。
