# power017：SC8585 首次及恢复后 ADC 读回

承接固定 GPU015/USB829 和 power016 的同一电源 worker/CONFIG2、3；不改变充电电流、电压、OVP、认证、泵使能、Data 代际或其他设备资源。普通充电控制实机基线仍为013，电量/供电读取为009。本轮尚未原生构建或上机。

## 已有证据与修改

016 同一次启动完成两次本驱动休眠/恢复、五次 USB 状态、一次正常 XNU 返回和安卓保护后验。休眠时 lifecycle3、CPU 样本和泵有效位为0；恢复后实际新读数有效。但启动第一样本及两次恢复后的第一泵样本均为 EIO5，随后恢复。日志完整性、正常 worker error0 与卷卸载已验证；它证明驱动最终恢复，没有证明首次 ADC 初始化正常或完整系统睡眠。

原厂 SC8585 的 ADC 初始化跳过 IBAT/TSBAT 两路，16h 的这两位在本机读取为0。旧代码却将它们设为1并按0x8f/0x06检查；真实生产代码在相同读回行为下复现首次 EIO。本轮只用0x89配置/恢复 VBUS、VBAT、TDIE，保留其他字段。15h 的配置/事件掩码保持原0xc9/0x88，20ms采样等待与GPIO114原厂400ms唤醒保持。

另外，旧代码在第一次 ADC 配置失败后保留 owned，下一次采样会绕过配置检查。真实生产代码也已复现。本轮每次采样均检查实际配置后再解码；owned仅表示可能已提交的操作。实际读回仍错误时持续无效，不重复写入；后续真实读回已确认时可恢复测量。

宿主回归包括模拟本机两位读回为0、三次首次ADC接续/恢复、其他扫描位保留与原值恢复，以及失败后不可绕过/真实观察后恢复且不重发写入。旧016两个独立场景都失败，新代码和全部既有泵场景通过ASan/UBSan；未改的核心、协议、控制、日志和PM回归按精确源码复用。

## 同轮真机验收

1. 固定源码与唯一原生构建，完成实际对象/ABI、严格预链接、固件/PAC、GPU015/USB、17入口、读盘/八核/显示/HID/电池类的必要资格。
2. 全资格后才协调113窗口；使用届时最新实际后验释放、磁盘payload写者和合法Data头，不沿用旧016释放后的历史状态。核新鲜指定Android/root、原目标映射/pin与GPT目标几何，原payload范围一次写入及临时boot，唯一r008。
3. 启动立即接续观察并保存本轮日志精确路径。需要原始首个P1的SC8585身份/ADC有效及cp_error0，不能用几秒后的正常读数替代。
4. 同次两轮CONFIG2/3。实际休眠3且CPU/泵有效位清零；恢复1后第一新P1即CP有效、error0，随后新gauge/charger/ADC有效。每阶段USB实际错误计数为0；命令ID、queued与实际完成分别保存。
5. 电脑供电/满电或能力不足时保持充电控制零写入/零owned；本轮不借PM验证触发高压或泵直充。
6. 取齐后一次当前session/seq的正常XNU返回，实际Android/root必要后验，停采集并只读取本方≤256KiB日志、核CRC/计数/头不变后立即释放。SSH查询中断按已有真实阶段续接，禁止重复payload、boot或返回命令。

仅驱动PM首采样、正常返回与保护通过后保留相应分项进展。原厂充电器9V/1500mA/连续180秒/恢复5V与原OVP、屏幕及完整系统睡眠继续待人类关闭无人值守后验；PPS、认证、泵直充与90W未完成，不升主包。沿原安卓/root/17/只读27根/generation1 Data不reset/容量/分区禁刷、两项固定复位0、单代理与本地私有资料边界。
