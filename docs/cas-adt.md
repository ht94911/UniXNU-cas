# cas Apple Device Tree generator

[简体中文](cas-adt.zh-CN.md)

The X-03 generator produces and audits a small Apple Device Tree (ADT) for the fixed cas CPU/platform kernel route. The host checks passed on 2026-10-24. Every audit still reports `boot_ready: false` and `hardware_tested: false`: current memory ownership, GOP state, exception level and XNU execution belong to later tasks.

## Inputs and commands

Run with Python 3.10 or newer. Generation uses only the standard library. The optional real consumer probe also needs Git, a C compiler and the fixed local framework/XNU inputs.

```sh
# Deterministic, entropy-free host fixture; never use it as a boot input.
python3 scripts/make-cas-adt.py --mode fixture --out /tmp/cas-adt-fixture-001

# Include the other seven observed affinities for host review only.
python3 scripts/make-cas-adt.py --cpu-profile all --mode fixture --out /tmp/cas-adt-all-001

# Verify the original local evidence as well as the generated contract.
python3 scripts/make-cas-adt.py --mode fixture \
  --evidence-root /mnt/i/Code/UniXNU-cas --out /tmp/cas-adt-traced-001

# New OS entropy; keep this output on a private Linux filesystem.
python3 scripts/make-cas-adt.py --mode private \
  --evidence-root /mnt/i/Code/UniXNU-cas \
  --out "$HOME/cas-private/adt-001"

python3 -m unittest discover -s tests -p test_cas_adt.py -v
```

Each output directory must be new. It contains `cas.adt`, `audit.json` and `provenance.json`. The latter maps every property, including each node's `name`, to a cas fact, an explicit software input or a schema policy. Reports contain the entropy length and file hash, never its bytes. Private mode requires effective POSIX owner-only access: directory `0700`, files `0600`. It refuses Windows/WSL filesystems that cannot enforce those modes; this was reproduced on the local I: DrvFS mount. Refusal can leave an empty directory, which must not be reused.

The facts file pins three original inputs by SHA-256: the local historical cas capture, `config/memory-map.json` and `config/display-profile.json`. `--evidence-root` verifies their bytes and independently derives the selected hardware values. Without it, source verification is explicitly `not_run`; this does not silently become a traceability pass. The repository contains the selected facts, not the raw capture or device identifiers.

## Wire format and consumption

`config/cas-adt-schema.json` is a machine-readable contract, not general JSON Schema. `scripts/adt_codec.py` encodes little-endian node/property counts, 32-byte property names and four-byte padded payloads. Decoding rejects duplicate names, nonzero padding, trailing/truncated bytes, invalid strings, integer truncation and excessive counts/depth/size. All generated bytes must survive decode/re-encode unchanged.

The contract pins framework `67e8ef0`, ArmCpu `1951cc8`, ArmDTPlatform `0d54470`, DarwinBoot `d099354` and XNU `d8b8029` / 10063.141.1. Full commits and twelve exact consumer file hashes are in the schema. This work keeps the existing iPadOS 17.7.11 / 21H461 reference target. The separately recorded donor version difference remains unresolved.

| Path / property | Encoding and reason |
| --- | --- |
| `/` | Root name `device-tree` for ArmDTPlatform matching; actual cas model and compatible strings. |
| `/chosen` | `osenvironment=main`; informational DRAM base/total; `darwinboot-memory-size` is one `u64` allocation request. |
| `/chosen/memory-map` | Empty for this no-ramdisk/no-trust-cache/no-addon input. The loader may later populate the copied tree. |
| `/cpus/cpuN` | `reg` and `timebase-frequency` are `u32`; `device_type` is exactly `cpu\0`. CPU0 is `running`; other entries are `waiting`. |
| `/arm-io/ranges` | Three `u64`: logical child base, physical parent base and length. The window encloses only the two GIC regions. |
| `/arm-io/intc` | `arm,gic-v3\0`; four `u64` for two relative base/length pairs; `u64` redistributor stride. |
| `/psci` | Observed `arm,psci-1.0`, `smc`. |
| `/timer` | Informational architectural timer description and original PPI cells. No `device_type=timer` or invented MMIO `reg`. |
| `/memory`, `/reserved-memory` | Historical RAM bank and reservation descriptions, using `u64` base/length pairs. They do not allocate or protect loader memory. |
| `/defaults`, `/options` | Required ArmDTPlatform nodes; `sleep-disabled=1`, empty options. |

The eight captured affinities are `0x000, 0x100, ... 0x700`. The default emits CPU0 only. Emitting all eight does not prove SMP; the fixed ArmCpu secondary path remains a later `sheng-smp` opt-in. The captured timer frequency is 19,200,000 Hz; its virtual timer PPI 11 maps to INTID 27, used directly by ArmCpu. Omitting the legacy timer device type avoids making `pe_identify_machine.c` treat this architectural timer as an MMIO timer.

GICD is `0x17a00000/0x10000`; GICR is `0x17a60000/0x100000`, stride `0x20000`. Both the encoded widths and translated physical addresses are audited.

The NVRAM proxy is a new empty 8 KiB CHRP v1 bank, not a device dump: a 32-byte Apple header, a `common` partition with 2 KiB of empty variable space and the remaining `free` partition. All partition checksums and the bank Adler32 are validated, generation is zero and variable count is zero.

DarwinBoot obtains the Apple tree from the **kernel path plus `.adt`**. Its request's `DeviceTree` path is an FDT input and is not the ADT delivery path. It allocates its owned window from the current UEFI map and fills `boot_args.Video` from current GOP. These interfaces must be connected during X-06.

## Memory roles and omitted fields

All intervals use half-open bounds. The static audit verifies three disjoint historical banks, 31 firmware/protected reservations and six MMIO ranges, with alignment, overflow, containment and overlap checks. Total captured bank size is `0x2f9900000` bytes; it is not a contiguous free interval.

The high candidate is `[0x100000000, 0x120000000)` (512 MiB), with a 256 MiB loader request. It fits a captured bank and avoids recorded reservations. **No current allocator ownership has been demonstrated.** The accepted firmware allocator remains only `[0x94000000, 0x9c000000)` (128 MiB), smaller than DarwinBoot's 256 MiB minimum. X-04/X-05 must resolve that gap before any XNU boot candidate.

The entire historical splash reservation `[0x9c000000, 0x9e300000)` is protected. The 1080×2340 display profile has no fixed framebuffer base, stride or pixel format; these must come from current GOP through `boot_args.Video`. No fake framebuffer node or XNU log address is emitted.

Unknown properties and nodes are rejected. No Apple serial/chip identity, MAC, UUID, copied entropy, root-volume binding, partition choice, saved NVRAM variables, RAMDisk, trust cache or GPU addon is imported from umi. Private mode adds only 64 fresh OS random bytes. Even its output remains an integration input awaiting later runtime gates.

## Host results and reproduction

The final host run passed **53 tests** covering malformed wire data, range boundaries, source paths, CPU/GIC widths, NVRAM corruption, forbidden fields, provenance, round trips and CLI output behavior. Both public fixtures are deterministic:

| Profile | Bytes | SHA-256 |
| --- | ---: | --- |
| CPU0 | 13,864 | `b0d09551ce2e8098953fa6679f52c63777f71b23812ce5aea21ca9186c65b9a4` |
| All eight, host only | 15,712 | `2ba1f2a320a556b99ce2e4a7f03c7aa103b3c940762dd04f148e18a2b1e141a4` |

A second check compiles the actual fixed XNU `device_tree.c`, exact DarwinBoot `AdtNode` function and exact CHRP header/checksum helpers. Host shims replace their kernel/UEFI dependencies; parser statements are retained. The harness checks the documented ArmCpu/ArmDTPlatform reads, but does not execute those complete drivers. Three positive inputs pass; truncation, a wrong CPU width, a wrong GIC translation and a bad NVRAM checksum each trip the relevant probe assertion. These four rejections describe the probe contract, not a claim that all production drivers safely reject every malformed tree.

```sh
python3 scripts/audit-cas-adt-consumers.py \
  --framework ../UniXNU \
  --xnu ../build/xnu-work \
  --evidence-root /mnt/i/Code/UniXNU-cas \
  --out "$HOME/cas-private/consumer-001"
```

The probe requires a little-endian 64-bit host. Fixed inputs are read only; exact source hashes and module commits are checked before compilation. Its new private output retains source notices, compiler identity, commands and per-case results. The management archive is `records/xnu-adt/xa01-001`; source and test artifacts there are separate from the authoritative writable checkout. No device operation or new firmware build occurred for X-03.
